# 벤치마크 공개 고지: 무엇을 공개했고 무엇을 지웠나

*영문판은 [BENCHMARK_DISCLOSURE.md](./BENCHMARK_DISCLOSURE.md)에 있습니다. 두 문서는 같은 사실을 말해야 하니, 서로 다른 곳을 찾으시면 결함이므로 이슈로 알려 주세요.*

이 저장소는 `bench/` 아래에 실제 측정 산출물을 공개합니다. 그중 일부 실행은 이 저장소에 들어 있지 않은, 제3자 소유의 비공개 애플리케이션을 대상으로 했습니다. 이 문서에서는 무엇을 측정했고, 공개하기 전에 무엇을 지웠고, 그래서 공개본으로는 무엇을 할 수 없는지를 숨기지 않고 적습니다.

## 1. 실제로 측정한 것

retrieval과 source를 비교한 벤치 라인 세 건(`2026-07-22`, `2026-07-24`, `2026-07-27`)은 실제로 운영 중인 외부 단일 페이지 웹 애플리케이션을 대상으로 돌았습니다. Vue 3와 Quasar, TypeScript로 만들었고 Pinia 스토어와 axios 기반 API 계층, 쿠키 세션 인증 흐름, 클라이언트 쪽 유휴 타이머를 갖춘 앱입니다. 벤치를 위해 새로 만든 fixture가 아니라 실제로 돌아가는 코드베이스였고, 이 도구 자신의 저장소가 아니라 도입처를 대표할 만한 프로젝트라는 이유로 골랐습니다.

실행은 전부 읽기 전용이었습니다. 대상 저장소에 커밋도, push도, 편집도 하지 않았습니다.

## 2. 공개본을 익명화한 이유

측정 대상이 제3자 소유의 비공개 독점 코드입니다. 산출물을 손대지 않고 그대로 공개하면 다음이 재구성 가능한 수준으로 함께 공개됩니다.

- 프로젝트와 저장소, 브랜치, 배포 환경의 이름
- 실제 모듈·컴포넌트 경로와 실제 심볼 이름
- 실제 API 엔드포인트 경로
- 로그인·세션·MFA·토큰 갱신 규칙과 상태 코드
- 세션 스토리지 키 이름과 그 내용을 보호하는 방식
- 업무 도메인 필드명과 내부 상태 코드
- 유휴 시간과 타임아웃 임계값
- 백엔드 호스트명과 개발 서버 주소

그래서 공개한 산출물은 지워 낸 결과물입니다. 두 가지 처리를 했습니다.

**첫째, 안정적인 가명으로 바꿨습니다.** 위 식별자는 모두 가명으로 치환했고, 같은 대상은 저장소 어디서든 늘 같은 가명을 씁니다. 산출물의 내부 정합성과 읽는 흐름을 지키기 위해서입니다. 가명은 꺾쇠괄호 안에 쓰고 파일이 아니라 역할을 가리킵니다. `<login-page>`, `<user-store>`, `<api-client>`, `<http-client>`, `<router-table>`, `<item-store>`, `<session-timeout-composable>` 같은 식입니다. 엔드포인트는 `/api/auth/login`이나 `/api/items` 같은 일반형으로, 스토리지 키는 `example_session_key_*`로 바꿨습니다. 대상 자체는 `benchmark-baseline` 브랜치의 `external-vue-quasar-app`으로 적었고, 거버넌스 측정에 함께 나오는 다른 저장소들은 `external-organization` 아래 `external-frontend-a`, `external-frontend-b`, `external-project-c`로 표기했습니다. 정확한 임계값과 내부 상태 코드는 근사치로 뭉개는 대신 `<expiry-status>`, `<refresh-signal-code>` 같은 역할명으로 대체했습니다.

원본과 가명을 잇는 대응표는 일부러 이 저장소에 두지 않았습니다.

**둘째, 답변 프로즈를 보류했습니다.** 원시 결과 파일(`bench/results/real-B*.json`)에는 모델 답변 전문이 들어 있었습니다. 비공개 소스를 꼼꼼히 읽고 함수 단위 흐름을 라인 번호까지 짚어 낸 답변이라, 가명 치환만으로는 공개할 수 있는 상태가 되지 않았습니다. 그래서 `tasks[].runs[].answer`를 모두 고지문으로 바꾸고 `answerRedacted: true`와 원문 길이 `answerOriginalChars`만 남겼습니다. 같은 디렉터리의 채점 워크시트는 채점 근거가 되는 짧은 문구, 그것도 원본을 되살릴 수 없는 문구만 인용하도록 했고, 길게 인용돼 있던 답변 전문은 판정과 그 근거를 유지한 공개용 요약으로 줄였습니다.

## 3. 바꾸지 않은 것

**측정값은 하나도 손대지 않았습니다.** 다음은 주변 문장이 허용하는 한 원본 그대로입니다.

- 입력·출력 토큰 수, wall-clock 시간, 도구 호출 횟수
- arm별·태스크별 점수, 루브릭 분수, 정확도 집계
- 표본 수와 반복 횟수(`N`), arm 정의와 arm 라벨
- 모델 식별자와 실행 날짜
- 실제로 던진 질문과 루브릭 구조
- 기록해 둔 한계와 유보, 부정적 결과, 정정. retrieval이 진 실행과 태스크도, 낡은 위키가 보안과 관련해 자신 있게 틀린 답을 낸 실행도 그대로 남겼습니다

측정값이 담긴 문장에 식별자가 섞여 있으면 식별자만 바꿨습니다. 다시 계산한 값은 없습니다. 태스크 파일과 보고서 파일명에 대상의 프로젝트명이 들어 있어 파일명도 가명으로 바꿨고(`bench/tasks-external-vue-app.json`, `bench/results/real-driver-external-vue-app-*.md`), 저장소 안의 참조를 전부 함께 고쳤습니다. 이름 변경은 `git mv`로 해서 파일 이력이 그대로 남아 있습니다.

## 4. 이 산출물로 할 수 있는 일과 할 수 없는 일

**할 수 있는 일은** 방법론과 arm 설계, 프롬프트, 루브릭, 채점 절차, 집계 코드, 전체 수치 기록을 검토하는 것입니다. 공개하는 이유가 바로 이것입니다.

**할 수 없는 일은 역사적 측정을 다시 돌려 보는 것입니다.** 측정 대상 corpus가 비공개이고 여기 함께 배포되지 않으므로, 그 코드베이스에 이미 접근 권한이 있는 분이 아니라면 같은 대상으로 완전히 재실행하실 수 없습니다. 이건 재현성의 실제 한계이고 익명화로 해결되지 않습니다. 익명화는 산출물을 공개할 수 있게 만들어 준 조치일 뿐, corpus를 대신해 주지는 않습니다.

## 5. 공개 harness fixture는 이것과 별개입니다

`bench/tasks.json`은 완전히 공개된, 위와는 별개의 태스크 세트입니다. 이 저장소 자신의 소스와 위키를 대상으로 한 코드 이해 태스크 6개이고, `bench/real/make-stub-wiki.mjs`가 `B2_empty` 통제군 fixture를 만듭니다. `node bench/real/runner.js --dry`를 돌리면 모델 호출도 비용도 없이 harness 전체를 검증할 수 있습니다.

이 fixture의 목적은 harness가 제대로 도는지 확인하는 것, 즉 smoke test입니다. `bench/results/`에 있는 역사적 수치의 출처가 아니며, 그 수치와 합산하거나 이어진 것처럼 제시해서는 안 됩니다. 이 저장소에 합성 Vue/Quasar fixture를 새로 만들지도 않았습니다. 공개된 자립 fixture가 이미 있었고, 두 번째를 만드는 일은 근거를 늘리지 못하면서 패키지 범위만 넓히기 때문입니다.

## 6. 지우지 못한 채 남은 노출

이번 작업의 한계도 그대로 적어 둡니다.

- **git 이력.** 이번 익명화는 현재 트리만 바꿉니다. 과거 커밋에는 원본 식별자가 그대로 남아 있고 이력 재작성은 하지 않았습니다. 이 변경의 날짜별 기록은 `docs/llm-wiki/log.md`에 있습니다.
- **비공개 저장소의 커밋 해시.** `docs/llm-wiki/HARNESS_GOVERNANCE_ROADMAP.md`의 거버넌스 측정 표에 남아 있습니다. 그 측정을 재현할 근거이고 해당 저장소에 접근하지 못하면 아무 의미가 없는 값이라 지우지 않았습니다.
- **아키텍처 관찰.** 측정 논거 안에 그대로 남습니다. 예를 들어 한 대상의 API 계층이 커다란 파사드 하나라는 사실은, 제안된 앵커 축소 규칙이 그 저장소에서 무효로 측정된 이유 자체입니다. 내용이 아니라 형상을 서술하는 것이고, 이 저장소가 이미 공개한 결론의 근거이기도 합니다.
- **이미 배포된 버전.** 이번 변경 이전에 나간 패키지와 그 산출물은 영향을 받지 않습니다.

## 7. 이 결과를 인용하는 방법

정확한 표기는 이렇습니다. *외부 비공개 Vue/Quasar SPA에서 측정 · 단일 저장소 · 단일 모델 · 6 태스크 · N=3 · 에이전트 채점(채점 기준은 표본 검토로 사람이 비준) · 공개 산출물은 제3자 기밀 보호를 위해 일부 삭제.*

"human-graded"라고 쓰면 안 되고, "재현 가능"이라고 해서도 안 되며, 굵은 헤드라인 수치로 뽑아서도 안 됩니다. `README.md`에 성능 헤드라인을 넣지 않기로 한 규칙은 이 문서 때문에 달라지지 않습니다.
