# 벤치마크 공개 고지 — 공개된 산출물이 무엇이고, 무엇을 지웠는가

*English: [BENCHMARK_DISCLOSURE.md](./BENCHMARK_DISCLOSURE.md). 두 문서는 같은 사실을 말합니다.
서로 다르다면 그것은 결함이니 이슈로 알려주세요.*

이 저장소는 `bench/` 아래에 실제 측정 산출물을 공개합니다. 그중 일부 실행은 **이 저장소에 포함되지
않은, 제3자 소유의 비공개 애플리케이션**을 대상으로 했습니다. 이 문서는 무엇을 측정했고, 공개 전에
무엇을 제거했으며, 따라서 공개본으로 무엇을 할 수 없는지를 그대로 밝힙니다.

## 1. 실제로 측정한 것

retrieval 대 source 벤치 라인(`2026-07-22`·`2026-07-24`·`2026-07-27`)은 **실재하는 외부 단일
페이지 웹 애플리케이션**을 대상으로 돌았습니다 — Vue 3 / Quasar / TypeScript, Pinia 스토어,
axios 기반 API 계층, 쿠키 세션 인증 흐름, 클라이언트측 유휴 타이머를 갖춘 앱입니다. 벤치를 위해
새로 만든 fixture가 아니라 **운영 중인 코드베이스**였고, 이 도구 자신의 저장소가 아니라
**대표성 있는 도입처 프로젝트**라는 이유로 선택됐습니다.

실행은 읽기 전용이었습니다. 대상 저장소에 커밋·push·편집을 하지 않았습니다.

## 2. 공개본을 익명화한 이유

그 대상은 **제3자가 소유한 비공개·독점 코드**입니다. 산출물을 그대로 공개하면 다음이 재구성 가능한
수준으로 함께 공개됩니다.

- 프로젝트·저장소·브랜치·배포 환경 이름
- 실제 모듈·컴포넌트 경로와 실제 심볼 이름
- 실제 API 엔드포인트 경로
- 로그인·세션·MFA·토큰 갱신 규칙과 상태 코드
- 세션 스토리지 키 이름과 그 내용의 보호 방식
- 업무 도메인 필드명과 내부 상태 코드
- 유휴/타임아웃 임계값
- 백엔드 호스트명과 개발 서버 주소

따라서 공개 산출물은 **redacted artifact**입니다. 두 종류의 처리를 적용했습니다.

**(가) 안정적 가명.** 위 식별자는 모두 가명으로 바뀌었고, 같은 대상은 저장소 전체에서 **항상 같은
가명**을 씁니다(산출물의 내부 정합성과 가독성 유지). 가명은 꺾쇠괄호로 쓰며 파일이 아니라 **역할**을
가리킵니다: `<login-page>`·`<user-store>`·`<api-client>`·`<http-client>`·`<router-table>`·
`<item-store>`·`<session-timeout-composable>` 등. 엔드포인트는 일반형(`/api/auth/login`·
`/api/items`), 스토리지 키는 `example_session_key_*`, 대상 자체는 `benchmark-baseline` 브랜치의
`external-vue-quasar-app`이며, 거버넌스 측정에 함께 등장하는 다른 저장소는
`external-organization` 아래 `external-frontend-a`·`external-frontend-b`·`external-project-c`로
표기합니다. 정확한 임계값과 내부 상태 코드는 근사치로 바꾸지 않고 역할명(`<expiry-status>`·
`<refresh-signal-code>`)으로 대체했습니다.

원본과 가명의 **대응표는 의도적으로 이 저장소에 두지 않습니다.**

**(나) 답변 프로즈 보류.** 원시 결과 파일(`bench/results/real-B*.json`)은 모델 답변 전문을 담고
있었습니다. 그 답변들은 비공개 소스를 정독한 결과 — 함수 단위 흐름에 라인 번호까지 — 였고, 가명
치환만으로는 공개 가능해지지 않습니다. 그래서 각 `tasks[].runs[].answer`를 고지문으로 대체하고
`answerRedacted: true`와 원문 길이 `answerOriginalChars`를 남겼습니다. 같은 디렉터리의 채점
워크시트는 채점 근거가 되는 짧고 비재구성적인 문구만 인용하며, 길게 인용돼 있던 답변 전문은 판정과
그 근거를 유지한 **공개용 요약**으로 줄였습니다.

## 3. 바꾸지 않은 것

**측정값은 하나도 바꾸지 않았습니다.** 다음은 (주변 문장이 허용하는 한) 원본 그대로입니다.

- 입력/출력 토큰 수, wall-clock 시간, 도구 호출 횟수
- arm별·태스크별 점수, 루브릭 분수, 정확도 집계
- 표본 수와 반복 횟수(`N`), arm 정의와 arm 라벨
- 모델 식별자와 실행 날짜
- 던진 질문과 루브릭 구조
- 기록된 모든 한계·유보·부정적 결과·정정 — retrieval이 **진** 실행과 태스크, 그리고 낡은 위키가
  보안상 자신 있게 틀린 답을 낸 실행까지 포함

측정값이 담긴 문장에 식별자가 있으면 **식별자만** 바꿨습니다. 재계산은 없습니다. 태스크 파일과
보고서 파일명에 대상의 프로젝트명이 들어 있어 가명으로 바꿨고(`bench/tasks-external-vue-app.json`,
`bench/results/real-driver-external-vue-app-*.md`) 저장소 안의 모든 참조를 함께 갱신했습니다.
이름 변경은 `git mv`로 해서 파일 이력이 보존됩니다.

## 4. 이 산출물로 할 수 있는 것과 할 수 없는 것

**할 수 있는 것:** 방법론, arm 설계, 프롬프트, 루브릭, 채점 절차, 집계 코드, 전체 수치 기록의 검토
— 공개하는 목적이 바로 이것입니다.

**할 수 없는 것 — 역사적 측정의 재실행.** 측정 대상 corpus는 비공개이고 여기에 배포되지 않으므로,
그 코드베이스에 이미 접근 권한이 있는 사람이 아니라면 **동일 대상에 대한 완전한 재실행은
불가능합니다.** 이것은 재현성의 실제 한계이고, 익명화로 해소되지 않습니다 — 익명화는 산출물을
공개할 수 있게 만든 이유일 뿐 corpus의 대체물이 아닙니다.

## 5. 공개 harness fixture는 별개다

`bench/tasks.json`은 **완전히 공개된 별개의** 태스크 세트입니다 — **이 저장소 자신의** 소스와 위키를
대상으로 한 코드이해 태스크 6개이며, `bench/real/make-stub-wiki.mjs`가 `B2_empty` 통제군 fixture를
만듭니다. `node bench/real/runner.js --dry`가 모델 호출도 비용도 없이 harness 전체를 검증합니다.

이 fixture의 목적은 **harness가 동작하는지** 확인하는 것입니다. harness smoke test입니다.
`bench/results/`의 어떤 역사적 수치의 출처도 **아니며**, 그 수치와 합산하거나 연속된 것처럼 제시해서는
안 됩니다. 이 저장소에 합성 Vue/Quasar fixture는 새로 만들지 않았습니다 — 공개된 자립 fixture가 이미
있었고, 두 번째를 발명하는 것은 근거를 늘리지 않으면서 패키지 범위만 넓히는 일이기 때문입니다.

## 6. 제거하지 못했다고 밝히는 잔여 노출

이번 작업의 한계를 그대로 적습니다.

- **Git 이력.** 이 익명화는 현재 트리만 바꿉니다. 과거 커밋에는 원본 식별자가 그대로 남아 있고
  이력 재작성은 하지 않았습니다. 이 변경의 날짜별 기록은 `docs/llm-wiki/log.md`에 있습니다.
- **비공개 저장소의 커밋 해시**는 `docs/llm-wiki/HARNESS_GOVERNANCE_ROADMAP.md`의 거버넌스 측정
  표에 남아 있습니다. 그 측정의 재현 근거이고 해당 저장소 접근 없이는 무의미하지만, 제거하지
  않았습니다.
- **아키텍처 관찰**은 측정 논거 안에 남습니다 — 예: 한 대상의 API 계층이 단일 대형 파사드라는 사실은,
  제안된 앵커 축소 규칙이 그 저장소에서 **무효**로 측정된 이유 자체입니다. 이는 내용이 아니라 형상을
  서술하며, 이 저장소가 이미 공개한 결론의 근거입니다.
- **이미 배포된 버전**의 패키지와 그 산출물은 이번 변경의 영향을 받지 않습니다.

## 7. 이 결과를 표기하는 방법

정확한 표기는 이렇습니다: *외부 비공개 Vue/Quasar SPA에서 측정 · 단일 저장소 · 단일 모델 ·
6 태스크 · N=3 · 에이전트 채점(채점 기준은 표본 검토로 사람 비준) · 공개 산출물은 제3자 기밀 보호를
위해 redacted.*

"human-graded"도, "재현 가능"도, 굵은 헤드라인 수치도 아닙니다 — `README.md`의 성능 헤드라인 금지
규칙은 이 문서로 인해 달라지지 않습니다.
