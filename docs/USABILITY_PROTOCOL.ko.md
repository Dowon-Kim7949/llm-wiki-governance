# 사용성 프로토콜: 처음 보는 사람이 README만으로 도입할 수 있는가

**상태: 준비만 했고, 아직 진행하지 않았습니다.** 지금까지 진행한 세션은 없습니다. 세션을 한 번이라도 하기 전까지 [VALIDATION.ko.md](./VALIDATION.ko.md)에서 독립 사용성은 **Unknown**입니다. 유지보수자의 에이전트가 대신 진행한 세션이나 모의 세션은 세지 않습니다.

## 참가자

- `llm-wiki-governance`를 써 본 적도, 읽어 본 적도 없는 개발자 한두 명.
- 유지보수자 본인은 안 되고, 이 도구를 만드는 과정을 지켜본 사람도 안 됩니다.
- 세션 전에 동의를 기록하고, 메모는 이름 없이 남깁니다.

## 준비

- 참가자 본인의 컴퓨터에 Node.js 18.18 이상과 git이 있어야 합니다. 이 프로젝트의 어떤 것도 미리 설치하지 않습니다.
- 참가자는 공개 자료만 읽을 수 있습니다. README, README가 링크하는 파일, `help <command>`입니다.
- 진행자는 돕지 않습니다. 예외는 테스트 프로젝트 밖을 건드릴 수 있는 단계 하나뿐입니다. 도움 요청은 하나도 빠짐없이 기록합니다.
- 참가자는 생각을 소리 내어 말합니다. 전체 시간은 60분입니다.

## 과제 A — 아직 코드가 없는 프로젝트(약 30분)

빈 디렉터리에서 진행합니다.

1. 새 프로젝트용 위키를 설정합니다.
2. 수용 기준이 있는 요구사항 하나를 기록합니다. 직접 써도 되고, 에이전트를 쓰는 사람이면 에이전트에게 맡겨도 됩니다.
3. 그 계획을 승인합니다.
4. 요구사항을 구현하는 작은 소스 파일과 테스트를 추가하고, 둘을 근거로 연결합니다.
5. 소스 파일을 바꿔 커밋하고, 어느 문서를 다시 봐야 하는지 찾아냅니다.

## 과제 B — 이미 있는 프로젝트(약 25분)

참가자가 잘 아는 작은 저장소나 `examples/python-fastapi-brownfield/app-src` 사본에서 진행합니다.

1. 문서 거버넌스를 설정합니다.
2. 코드의 한 영역에 대해 위키가 뭐라고 하는지 찾습니다.
3. 인용 하나가 없는 대상을 가리키게 만들고, 무엇이 그것을 보고하는지 확인합니다.
4. 인용된 파일을 바꾸고, 무엇을 갱신해야 하는지 찾아냅니다.
5. finding 하나를 해소합니다.

## 체크리스트(과제마다 끝나고 묻습니다. 1~5점과 한 문장으로 답합니다)

| # | 질문 |
| --- | --- |
| 1 | 명령을 실행하기 전에 그 명령이 무엇을 하는지 알았나요? |
| 2 | 다른 문서 없이 README만으로 시작할 수 있었나요? |
| 3 | 예상하지 못한 설정 단계가 있었나요? |
| 4 | 무언가 실패했을 때, 메시지만 보고 다음에 할 일을 알 수 있었나요? |
| 5 | 승인된 계획과 구현된 코드를 구분할 수 있었나요? |
| 6 | 어떤 명령이 읽기만 하고 어떤 명령이 파일을 바꾸는지 알았나요? |
| 7 | 공개 문서에 없는 것이 필요했나요? |
| 8 | 가장 헷갈리거나 막힌 곳은 어디였나요? |

## 기록할 것

- 단계별 걸린 시간. 끝내지 못했다면 멈춘 단계.
- 오류 메시지 원문 전부와, 그다음에 참가자가 한 행동.
- 참가자가 연 문서와 `help` 주제.
- 도움 요청 전부와 그 내용.
- 체크리스트 답변. 고치지 않고 그대로 기록합니다.

## 초대 문구(유지보수자가 보냄)

> AI가 쓴 프로젝트 문서를 관리하는 작은 오픈소스 CLI(llm-wiki-governance)를 만들고 있습니다. 이 도구를 한 번도 본 적 없는 개발자 한 분이 본인 컴퓨터에서 README만 보고 1시간 정도 써 봐 주셨으면 합니다. 작은 과제 두 개를 생각을 소리 내 말하면서 진행하시면 되고, 저는 보면서 메모만 합니다. 테스트 폴더 밖 파일을 건드릴 일이 아니면 돕지 않습니다. 참가자나 코드에 관한 내용은 공개하지 않습니다. Node.js 18.18 이상과 git만 있으면 됩니다. 참여해 주실 수 있을까요?
