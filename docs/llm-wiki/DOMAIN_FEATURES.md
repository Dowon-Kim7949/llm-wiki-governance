# Domain Features

명령어군을 넘는, 사용자가 체감하는 기능 단위를 소스 근거와 연결합니다.

## Features

- **프로젝트 자동 감지** — `src/detector.js`가 Node(`package.json`)뿐 아니라 Python(`pyproject.toml`/`requirements.txt` 등)·Go(`go.mod`)·Rust(`Cargo.toml`)·JVM(`pom.xml`/`build.gradle`)·PHP(`composer.json`)·Ruby(`Gemfile`)·.NET(`*.csproj`/`*.fsproj`) 매니페스트 신호로 `frontend/backend/fullstack/library` 유형과 생태계·주 매니페스트(`primaryManifest`)를 추론한다. 1.12부터 `mobile` 유형도 감지한다(Android Gradle 플러그인/AndroidX/AndroidManifest.xml, Flutter `pubspec.yaml`, Apple/iOS Podfile·`*.xcodeproj`·Package.swift, React Native `react-native` 의존성). 1.13부터 `infra` 유형도 감지한다(Docker `Dockerfile`·Compose, Kubernetes(apiVersion+kind YAML), Helm `Chart.yaml`, Terraform `*.tf`) — 단 앱 신호가 없을 때만 선택되는 fallback이라 컨테이너화된 앱 레포는 앱 유형을 유지한다. 1.14부터 Go `net/http`·Python stdlib HTTP 서버를 소스에서 감지하면 해당 생태계를 `library`가 아닌 `backend`로 단방향 승격한다. 1.14.1부터 매니페스트/소스 읽기가 BOM 인식이라 UTF-16(LE/BE)·UTF-8 BOM으로 저장된 매니페스트(Windows에서 저장된 `requirements.txt` 등이 mojibake로 `library` 오분류되던 문제 교정)도 올바르게 디코드한다. `--type`로 명시 override 가능 — 2026-07-27 감사부터 이 값도 `--format`/`--lang`처럼 검증돼(단일 소스 `src/detector.js#symbol:KNOWN_TYPES` = frontend/backend/fullstack/library/mobile/infra/mixed/unknown) 미지원 유형은 usage error(exit 3)다. 이전엔 `--type banana`가 그대로 detection에 흘러 `active_profiles: core, banana`를 냈다.
- **초기 문서 생성** — `init --write`가 core + profile 문서와 선택 adapter를 생성한다. backend/fullstack에서는 업무 도메인을 감지해 도메인별 문서(`domains/NN_<name>.md`, `doc_type: domain`, `source_files`=탐지 경로)를 만들고 `domains/00_overview.md`에서 상대링크로 연결한다. 두 컨벤션을 모두 잡는다: **디렉터리 도메인**(`domains/domain/modules/features`의 직속 하위 폴더)과 **파일 도메인**(`endpoints/routers/routes/resources/controllers/handlers`의 소스 파일, 예: FastAPI `app/api/api_v2/endpoints/hazard.py`). frontend/mobile(SPA)에서는 별도 `detectFrontendDomains`가 도메인을 잡는다: `pages`/`views`/`features`/`modules`/`screens` 하위 1-depth 폴더와, vue-router/react-router 라우트 파일(`router.*`/`routes.*` 또는 `router/`·`routes/` 하위)의 최상위 라우트 그룹을 정규식으로 파싱(파서 의존성 없음)한다 — SPA UI 배관 폴더(components/layouts/composables/assets 등)는 제외. 백엔드/풀스택 탐지 경로는 불변(byte-identical). bounded 탐색·제외 가드로 오탐을 0에 가깝게(vendored/venv/test/dunder 제외, 집계자 파일명 제외). 1.14.4부터 가상환경·의존성 트리를 확실히 배제한다: `pyvenv.cfg`를 가진 디렉터리는 venv로 간주해 통째 스킵(이름 무관 — `venv3.10`·`.venv-py39` 등), `site-packages`/`dist-packages`와 버전형 `venv*`/`env<N>` 이름도 제외 — 그래서 설치된 라이브러리(passlib `handlers/`, boto3 `resources/`)가 도메인으로 오탐되지 않는다. 결정적 정렬·파일↔폴더 slug 병합. 기존 파일은 기본 보존, `log.md`는 append-only. 범위는 `GATE_REVIEW.md`(Gate 10). 도메인 문서가 계획되면(자동 탐지 또는 `--domains`) 상위 두 진입점에도 사전 배선한다(외부 피드백 P6, orphan 방지): `index.md`가 `domains/00_overview.md`를 읽기 순서·`related`로 링크하고, `DOMAIN_FEATURES.md`가 `## Domains` 섹션으로 각 도메인 문서를 마크다운 링크한다(overview↔per-domain 배선의 보완). 도메인이 없으면 두 문서는 byte-identical.
- **frontmatter 계약 검증** — 필수 필드/status enum/날짜 형식/배열 형태를 검증하고, `verified`는 `--strict`에서 리뷰 메타를 요구한다. 2026-07-27 감사부터 **중복 frontmatter 키**도 잡는다: 파서는 last-wins 의미론을 유지하되(기존 문서 형태 불변) 같은 키가 두 번 이상 나타나면 `frontmatter.duplicate_key`(warning, config `rules`로 off/escalate 가능)를 낸다 — 중복 키는 눈에 보이는 오류 없이 grounding(앞선 `source_files`/`evidence` 리스트)을 버리거나 `status`/`contains_sensitive_info`를 뒤집을 수 있어서다. finding에는 키 이름만 표시되고 값은 절대 노출되지 않는다(`--lang ko` 지역화 포함). 근거: `src/frontmatter.js#symbol:parseFrontmatter`.
- **근거 추적** — `source_files`(넓은 근거)와 `evidence`(파일/라인/심볼/섹션/라우트 정밀 근거)를 검증하고 본문 `## Evidence` 정렬을 확인한다. 1.14.2부터 `evidence`는 `파일#L10` 외에 콜론-라인 표기(`파일:10`·`파일:10-20`)도 동등하게 수용한다(에디터/grep 스타일 근거가 헛 `evidence.missing`을 내지 않음). 본문 `## Evidence` 정렬 검사(`evidence.section_unlisted`)도 verbatim 문자열이 아니라 **소스 경로 기준**으로 매칭한다: frontmatter가 `파일#L60-L70`이고 본문이 `파일:60-70`이거나(또는 `#symbol:`/`#section:` locator 차이) 같은 경로만 언급해도 통과 — locator 형식 차이로 인한 헛 경고를 없앴다(외부 `http(s)`/`repo:` 참조는 여전히 verbatim 매칭; 경로 경계 검사로 `src/cli.js`가 `src/cli.js.map`에 오매칭되지 않음).
- **연결성 검증** — 로컬 markdown 링크, 위키 링크(이중 대괄호 표기), `related` 항목의 존재성을 검증한다(`related.missing`).
- **enrichment 신호** — placeholder만 남은 미보강 문서를 `content.not_enriched`로 표시해 "빈 스캐폴드가 통과"하는 것을 막는다.
- **지식 그래프** — `wikiGraph`가 문서→문서 엣지(wiki/related/markdown 링크)·미해결 개념·별칭·고아 문서를 집계한다. `llm-wiki graph`가 이를 text/JSON/Mermaid/DOT로 내보내고, `llm-wiki stats`가 헬스 스코어(verified%/enrichment%/evidence coverage/staleness)를 보고한다. `--format html` 대시보드에는 탐색용 Document Index가 있다.
- **에이전트 인수인계** — `handoff`/`prompt`가 코드 근거로 문서를 보강하도록 유도하는 반복 프롬프트를 출력한다. 1.14.1부터 `handoff` 진입점은 명시적으로 선택된 에이전트의 어댑터 파일만 나열하고, 미선택 시 `docs/llm-wiki/index.md`만 가리켜 setup이 생성하지 않은 `AGENTS.md`/`CLAUDE.md`를 먼저 읽으라고 하지 않는다. 같은 1.14.1에서 `Next Step`이 "이 프롬프트는 CLI가 실행하는 게 아니라 코딩 에이전트(Claude Code/Codex)에 붙여넣는 지시문"임을 3단계(붙여넣기→코드 근거 보강→사람 검토·verified)로 설명하도록 명료화했다. 외부 피드백 P5로 `next`가 미완(`content.not_enriched`) 문서별 **Enrichment Checklist**를 추가로 출력한다: 각 문서에서 아직 placeholder가 남은 `##` 섹션과 채울 힌트를 나열해(순수 헬퍼 `enrichmentChecklist`, audit finding의 additive `checklist` 필드) 에이전트가 "무엇을 어디에 채울지"를 즉시 안다. `next`에 `enrich-placeholder-docs` 액션도 추가됐다.
- **스킬 생성(자동화 프롬프트)** — 1.15부터 `init`/`quickstart`이 `bootstrap`/`feature`/`fix`/`docs-sync` 위키-그라운디드 워크플로를 각 에이전트 네이티브 형식의 **호출 가능한 아티팩트**로 생성한다: Claude 스킬(`.claude/skills/llm-wiki-<task>/SKILL.md`, `/llm-wiki-feature`로 호출)·**Codex 스킬(`.agents/skills/llm-wiki-<task>/SKILL.md`)**·Cursor 룰(`.cursor/rules/llm-wiki-<task>.mdc`)·에이전트-중립 프롬프트(`.llm-wiki/prompts/llm-wiki-<task>.md`, 그 외 에이전트). 각 본문은 `src/task-prompts.js` 워크플로를 재사용한다. 도메인 맵은 1.25.0부터 **`bootstrap`만** 생성 시점 스냅샷(`docs/llm-wiki/domains/`)을 주입하고, **`feature`/`fix`/`docs-sync`는 실행 시점에** `llm-wiki prepare --task ... --compact`(또는 `onboard`)로 현재 맵을 조립해 고정 본문이 stale되지 않고 도메인 수와 무관하게 유지된다. 1.25.0의 `--refresh`(`init`/`quickstart`)는 content-hash 마커로 **사용자가 수정하지 않은 관리 스킬만** 갱신하고 사용자·커스텀 스킬은 절대 덮어쓰지 않는다. `--skills`(모든 네이티브 형식) 또는 `--agent claude|codex|cursor`(해당 에이전트의 네이티브 형식)로 opt-in, preview-first, 기존 파일 미덮어씀, **recognize-don't-run**(도구는 생성만, 실행은 에이전트), needs_review 규율 본문 내장. `bootstrap` 태스크는 `init --write`가 만든 뼈대를 **실제 코드 근거로 최초 보강**하는 전용 워크플로로, 지금까지 `handoff` 프롬프트가 일회성으로 하던 그 절차를 반복·일관 실행하게 만든다 — 규칙은 단일 소스(`src/task-prompts.js#symbol:initialEnrichmentWorkflow`)에서 `handoff`와 **공유**해 둘이 절대 갈라지지 않는다. 생성한 위키가 실제 기능 작업에 쓰이도록 하는 진입점이다. **재시작 요건**: Claude Code는 스킬을 세션 시작 시점에 로드(hot-reload 아님)하므로, 갓 생성한 스킬은 에이전트를 재시작해야 `/llm-wiki-*`로 나타난다 — 이 때문에 생성 직후 명령이 "unknown"으로 보일 수 있어, `init`/`quickstart` 출력이 스킬을 실제로 만들었을 때만 재시작 안내 한 줄을 표시한다. 2026-07-28(ECC 기법 추출, 미릴리스)부터 모든 생성 아티팩트가 **토큰 예산 메타**를 갖는다: Claude/Codex SKILL.md는 frontmatter `estimated-tokens: <N>`(값이 chars/4 **PROXY**임을 인라인 주석으로 항상 동반 — 실측 토큰 주장 금지 정책), Cursor `.mdc`·중립 프롬프트는 서드파티 frontmatter 계약을 깨지 않도록 본문 선두 HTML 코멘트로 같은 수치를 싣는다(`retrieval.js#estimateTokens` 재사용). 에이전트/사람이 스킬을 **로드하기 전에** 비용을 가늠하게 하는 ECC 차용 기법이며, 구세대(예산 없는) 관리 스킬은 `--refresh`가 정상 갱신한다(마커 v2→v3). 근거: `src/commands/skills.js#symbol:writeSkillArtifacts`(생성), `src/commands.js#symbol:quickstartInitSummary`(재시작 안내), 범위는 `GATE_REVIEW.md`(Gate 21, accepted).
- **범위 한정 자동수정(`fix`)** — `fix`가 승인된 좁은 범위의 안전한 수정만 적용한다: 누락 Tier A frontmatter 필드 삽입, frontmatter `evidence` 기준 본문 `## Evidence` 섹션 보완, 깨진 related/markdown 링크에 대한 `needs_review` 스텁 생성, 수정 문서의 `last_updated` 갱신. 기본은 미리보기이고 `--write` 시에만 쓴다. `verified` 문서 내용·`docs/llm-wiki/` 밖 파일·`source_files`/`evidence` 값·Tier B 필드(title/doc_type/project/author)·미보강 내용은 건드리지 않는다. 근거: `src/commands/fix-migrate.js#symbol:fixCommand`, 범위 결정은 `GATE_REVIEW.md`.

## Detection & Enrichment Heuristics (transparency)

탐지와 미완 판정은 **결정적 휴리스틱**이다(외부 피드백 P7: 회귀 방지 + 판정 기준 공개). 아래 각 규칙에는 유닛/스냅샷 테스트가 있다(`tests/verification.test.js`의 `detectDomainDirectories`/`detectFrontendDomains`/`planDomainDocs` 스냅샷·`enrichmentChecklist`).

- **도메인 부모 인식**: 디렉터리 도메인 = `domains`/`domain`/`modules`/`features`의 직속 하위 폴더(`DIR_DOMAIN_PARENTS`); 파일 도메인 = `endpoints`/`routers`/`routes`/`resources`/`controllers`/`handlers`의 소스 파일(`FILE_DOMAIN_PARENTS`); frontend/mobile = `pages`/`views`/`features`/`modules`/`screens`의 1-depth 폴더 + vue/react-router 라우트 그룹(`FRONTEND_DIR_DOMAIN_PARENTS`).
- **제외(오탐 방지)**: 기술 폴더 `common`/`shared`/`core`/`utils`/… (`DOMAIN_EXCLUDE_NAMES`); 순회 배제 `node_modules`/`dist`/`build`/venv(`pyvenv.cfg` 마커·`site-packages`·버전형 `venv*`/`env<N>`)/test/docs (`DOMAIN_TRAVERSAL_SKIP`); 파일 집계자·인프라 이름 `index`/`main`/`app`/`router`/`base`/`schemas`/`models`/`types`/… (`FILE_DOMAIN_EXCLUDE`); SPA UI 배관 `components`/`layouts`/`composables`/… (`FRONTEND_EXCLUDE_NAMES`); dunder(`__`)·hidden(`.`) 접두. 라우트는 동적 세그먼트(`:id`, `*`)·빈 세그먼트를 버린다. 정확한 집합은 `src/commands/domains.js`가 단일 소스다(이 목록은 대표 예시).
- **`content.not_enriched` 판정**: 본문이 생성 시 placeholder 문구(`ENRICHMENT_PLACEHOLDER_SENTINELS`)를 하나라도 포함하면 미완으로 flag한다(`templates/`는 제외). `llm-wiki next`가 문서별로 아직 placeholder가 남은 `##` 섹션을 Enrichment Checklist로 보여주고(P5), `llm-wiki explain content.not_enriched`가 조치법을 안내한다.
